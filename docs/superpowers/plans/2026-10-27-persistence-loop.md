# Persistence loop implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add timestamped backups with retention, diff, restore, optional verify, and a model detail card around the per-model LM Studio defaults introduced earlier.

**Architecture:** Extend `lmstudio_defaults.py` with backup/diff/restore helpers and a new `lmstudio_default_verify.py` for the async echo check. Add thin API, CLI and UI adapters. Keep all file logic in the service and test it without a live LM Studio server.

**Tech Stack:** Python 3.11+, FastAPI, Typer, pathlib, httpx client, vanilla JS.

**Spec:** `docs/specs/2026-10-27-persistence-loop-design.md`

## Global Constraints

- Backup files are created only inside the defaults directory; names are generated by the service, never accepted as paths.
- Restore validates the backup JSON before writing anything; invalid or unreadable files raise `DefaultsError`.
- `verify` loads with an empty `LoadConfiguration()` so LM Studio resolves the saved default; it always unloads in `finally`.
- No real LLM/hardware load during implementation; `verify` is tested with a fake client.
- Keep the existing `1387` tests green; add new tests rather than weakening old ones.
- Cache-bust JS imports only when a JS file changes.

## Review Focus

1. A restore from a backup that is byte-identical to the current file must not create a second backup or write anything.
2. `verify` must unload even when the load raises or returns no `load_config`.
3. A backup filename containing `..` or a path separator must be rejected before any file read.
4. Diff alignment with legacy `llama.speculativeDecoding.*` keys must match the writer's alignment.
5. `gpu_ratio` and rope fields are reported as `unverified`, never as verified or as mismatches.

```python
class FakeClient:
    def __init__(self, *, loaded_config=None, success=True, identifier="inst-1", unload_ok=True):
        self.loaded_config = loaded_config
        self.success = success
        self.identifier = identifier
        self.unload_ok = unload_ok
```

```python
async def verify_defaults(model_id, config, *, client, home=None):
    expected = expected_echo_fields(config)
    unverified = [attr for attr in ("gpu_ratio", "rope_freq_base", "rope_freq_scale")
                  if getattr(config, attr, None) is not None]
    identifier = None
    try:
        response = await client.load_model(model_id, LoadConfiguration())
        if not response.success:
            return {... error=response.error, unloaded=False}
        identifier = response.identifier
        loaded = response.loaded_config
        if loaded is None:
            return {... error="server did not return load_config", unloaded=...}
        actual = loaded.model_dump(exclude_none=True)
        mismatches = {k: {"expected": v, "actual": actual.get(k)}
                      for k, v in expected.items() if actual.get(k) != v}
        return {
            "verified": not mismatches,
            "checked": {k: {"expected": v, "actual": actual.get(k),
                            "match": actual.get(k) == v} for k, v in expected.items()},
            "mismatches": mismatches,
            "unverified": unverified,
            "unloaded": False,  # updated after unload
            "error": None,
        }
    except Exception as exc:
        return {... error=str(exc), unloaded=False}
    finally:
        unloaded = False
        if identifier is not None:
            try:
                await client.unload_model(identifier=identifier)
                unloaded = True
            except Exception:
                unloaded = False
        # patch the result's unloaded flag
```

Because the `finally` runs after `return`, the returned dict cannot be mutated easily. Structure the function with a helper that always returns after unload: use a try/except/finally where the result is stored in a local `result` and `finally` sets `result["unloaded"]`, then return result at the end. Implement that.

## Self-review

1. Spec coverage: every design section maps to a task (backups -> Task 1, restore -> Task 2, diff -> Task 3, verify -> Task 4, API -> Task 5, CLI -> Task 6, UI diff -> Task 7, model card -> Task 8, docs/verify -> Task 9).
2. Step scan: each step is one action with a checkable result; no "handle edge cases" placeholders.
3. Type consistency: `BackupEntry`, `DefaultsDiff`, `DefaultsRestoreResult` are introduced in Tasks 1-3 and consumed by name in Tasks 5-6; verify result is a plain dict as specified.
4. Review Focus: each of the five items has a test in Tasks 1-4.
5. Proportion: the plan is shorter than the spec's implementation surface; code bodies are left to the implementer except where the spec pins exact values.
